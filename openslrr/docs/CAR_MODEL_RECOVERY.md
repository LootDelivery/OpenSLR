# Модель автомобиля, извлечённая из `StreetLegal_Redline.exe`

Документ фиксирует, что именно удалось достать из **оригинального бинарника и его
скриптов** для машины целиком: двигатель, наддув, КПП, сцепление, привод, шины,
подвеска, тормоза, аэродинамика, износ и расходники. Каждое утверждение помечено
уровнем достоверности:

- **[КОД]** — прочитано в декомпилированном коде exe (Ghidra, 4393 функции),
  указан адрес функции;
- **[СКРИПТ]** — прочитано в декомпилированном TUFA-классе игры (`.class` → `.java`);
- **[ВЫВОД]** — следствие из кода, но без прогона; требует проверки;
- **[ОТКРЫТО]** — пока не восстановлено, см. §11.

Артефакты и инструменты, которыми это получено, — в §12.

## 1. Два слоя и цикл обновления

Игра состоит из двух исполняемых слоёв, и физика делится между ними.

| Слой | Что там | Где |
|---|---|---|
| Скрипты (TUFA) | параметры деталей, компоновка, тюнинг, передача констант в `Chassis` | `parts/**/*.class`, `cars/**/*.class` — 1576 классов |
| Native (x86) | вся симуляция: двигатель, трансмиссия, шины, подвеска, износ | `StreetLegal_Redline.exe`, .text 1.99 МБ |

Скрипт не считает физику. Он заполняет объект `java.game.parts.bodypart.Chassis`
(и объекты деталей), а native читает эти поля **по имени** и раскладывает в
собственные структуры.

Ключевые native-функции конвейера:

| Адрес | Роль |
|---|---|
| `0x00416B00` | регистратор native-методов: `(class, name, signature, fn*)` |
| `0x0043E3E0` | конструктор-копировщик объекта физики автомобиля (0xC1C байт) |
| `0x004421xx` | `Chassis.*` natives (23 шт.), включая `getTorque`/`setTorque` |
| `0x00448430` | **загрузка параметров автомобиля**: `Chassis` → структура физики |
| `0x00454500` | **главный шаг физики автомобиля** `step(car, dt)` |
| `0x0046B530` | регистрация natives `DynoData` / `Part` |
| `0x004B77F0` | **дино-свип**: перебор RPM и построение таблиц момента |
| `0x004B6BF0`, `0x004B7020`, `0x004B7740` | физическая модель цикла (термодинамика) |
| `0x0043BE70` / `0x0043BEE0` | интерполяция таблиц момента `torque(RPM)` / `torque2(RPM)` |
| `0x0043C520` | запись значений из деталей в состояние автомобиля (каналы 5…10) |

Порядок: деталь установлена → `fillDynoData`/`updatevariables` (скрипт) → native
собирает таблицы момента → `0x00448430` переносит всё в структуру физики →
`0x00454500` считает шаг.

Размер структуры физики — **0xC1C** байт; размер записи колеса — **0x2B4** байт;
жёсткое тело колеса индексируется страйдом **0xD4**.

### 3.2 Геометрия и производные величины — `0x004B69A0` **[КОД]**

```
bore_2      = bore                       (радиус = bore/2, передаётся как *0.5)
radius      = bore_2                     (диаметр цилиндра)
area        = π · bore_2²
displacement= area · (2·bore_2)          (0x19)
crank_len   = 2 · bore_2
V_total     = area · stroke + Vmin       (0x1c)
compression = V_total / Vmin             (0x1d)
rpm_limit   = (45.0 / bore_2) · 9.549296 (0x23)
```

и `0x004B6A80`:

```
P_boost_ratio  = P_boost / (1 + P_boost)   (0x14c)
P_boost_frac   = 1 / (1 + P_boost)         (0x150)
P_manifold     = P_x · 9.869233e-06 · T    (0x7c, 0x80)   // атм → МПа
```

### 3.3 Дино-свип — `0x004B77F0` **[КОД]**

Для каждой точки `rpm = step, 2·step, … < limit`:

1. `0x004B6BF0` — пересчёт состояния (наполнение цилиндра, фазы, зажигание).
2. `0x004B68C0` + `0x004B7740` — один рабочий цикл; затем **до 10 итераций**
   до сходимости: `|M_prev / M_new − 1| < 0.05`, с релаксацией
   `M = 0.6·M_new + 0.4·M_prev`.
3. Запись `torque[rpm]` (поле `0x62`) и `HP[rpm]` (поле `0x65`) в таблицы.
4. По ходу копятся `maxTorque`, `RPM_maxTorque`, `maxHP`, `RPM_maxHP`.

То есть момент — не формула, а **результат установившегося цикла**, посчитанного
физически. Функция `FUN_004B77F0` вызывается только из `0x0046AA20`
(`DynoData.calcDyno`) — **в рантайме термодинамика не считается**; в игре работают
только готовые таблицы.

`0x004B7740` дополнительно считает:
`BSFC = (fuel/air) / (0.6·bore)`, `fuel_flow = (torque·3600/rpm)·2.2`,
нормировку расхода на цикл.

### 3.4 Что видит физика — интерполяция таблиц **[КОД]**

`0x0043BE70(rpm, physics)` — таблица №1, `0x0043BEE0` — таблица №2 (наддув/закись).
Обе — **кусочно-линейная интерполяция** по точкам `{rpm, M}`:

```
M(rpm) = M[i-1] + (rpm − rpm[i-1]) · (M[i] − M[i-1]) / (rpm[i] − rpm[i-1])
```

Важное следствие: **ниже первой и выше последней точки таблицы момент = 0**
(функция возвращает 0), а не «продолжение кривой».

### 3.5 Рантайм-модель двигателя — `0x00454500` **[КОД]**

Порядок внутри шага (проверено чтением кода):

```
rpm_rad   = car.rpm · 9.549296⁻¹…            (об/мин → рад/с)
throttle  = clamp(|car.throttle|, 0, 1)

// потери
если rpm_rad > 0:  M_fric = −(rpm/(0.05·maxRPM))·(0.05·maxRPM)²·friction_fwd
иначе:             M_fric = +rpm²·friction_rev
оба варианта дополнительно ограничены членом −0.5·rpm·engine_inertia (берётся минимум)

// полезный момент
M = torque_table_1(rpm_rad) · car.mult_normal       // 0x1DD0

// стартер
если |throttle| ≤ 0.1 и rpm < 0.95·idle_rpm:  M += starter_torque; starter = 1

// закись
если nitro_amount > 0.1 и nitro_tank > 0 и consumption_nitro > 0:
    M += (torque_table_2(rpm)·car.mult_nitro − M) · nitro_amount · limiter
    nitro_tank −= rpm·0.0002·nitro_amount·limiter·dt·consumption_nitro

// отсечка (по темпу, не по «жёсткому» порогу); код 0x004547xx
rate = (rpm − rpm_prev) + rpm
frac = 1.0
eсли rate ≤ limit:
    если rpm > limit:  frac = (limit − rate) / (rpm − rate)
иначе (rate > limit):
    если rpm > limit:  frac = 0.0
    иначе:             frac = (limit − rpm) / (rate − rpm)
M *= frac
rpm_prev = rpm
```
То есть отсечка режет момент **пропорционально приближению к лимиту за шаг**, а не
обнуляет его по достижении порога.

Затем `car.torque_at_clutch = 2 · M · throttle` (`0x1E28`) и момент уходит в колёса
через передаточное число (см. §4).

**Износ двигателя** (`car+0x1E38`) растёт при перекруте:
`f = (|rpm| / maxRPM)⁹`, `w += f·(1 + (0.01·|rpm−90|)²)·dt/τ·friction·100`.
Влияние: множитель `1 − w²·0.6`, при `w ≥ 1` → `0.1` и дополнительно `×0.5`,
а трение `friction_fwd/rev × 50` — то есть перекрученный двигатель резко теряет
мощность и начинает тормозить.

### 3.6 Опоры двигателя **[КОД]**

Двигатель колеблется на опорах как одномассовая система:
```
mass      = engine_mass · 8000
k         = physics[0xA48] / mass           // при малом ходе
k_динам   = ((ωё²+|v|²)·[0xA50] + [0xA4C])·wearfactor + [0xA48]) / mass
x'' = (M·throttle·1000)/mass − |dx|·[0x1E64]·dx·dt
```
Износ опор (`0x1E48`) накапливается, когда ход > 100.

### 3.8 `ClutchF` — мёртвый параметр (важный факт)

`ClutchF` (`Chassis.ClutchF = 500.0`, у деталей `Clutch.maxF = 500.0`) читается в
`0x00448430` и кладётся в `physics+0xC8`. В главном шаге физики (`0x00454500`)
**обращения к `+0xC8` нет ни одного** — проверено поиском по всему корпусу
декомпиляции. Сцепление моделируется не силой, а множителем
`engage = 1 − clutch` (поле `car+0x1DBC`), который масштабирует момент, идущий в
колёса.

Практический вывод для OpenSLRR: ограничение момента «по `ClutchF`» — не
оригинальное поведение; оригинал ограничивает сцепление только входным
значением `clutch` (0…1), которое приходит из скриптов/ввода.

## 4. КПП, сцепление, привод, дифференциал

Скрипты (`Transmission`) **[СКРИПТ]** пишут в `Chassis`:
`gears`, `ratio[8]` (индексы 1…6 — вперёд, `[7]` — задний, отрицательное число),
`rearend_ratio` (`end_ratio`), `starter_torque`, `diff_lock`, `drive_type`
(`DT_FWD=1`, `DT_RWD=2`), `drive_front` (доля момента на переднюю ось);
`fillDynoData` раскладывает привод по колёсам через `WheelRef.setDrive(...)`:
передние получают `drive_front`, задние `1 − drive_front`.

Native-шаг **[КОД]** — полная модель привода `0x00456xxx`:

```
total_ratio = rearend_ratio · ratio[gear]

// 1. приведённые инерции и коэффициент связи
J_engine  = engine_inertia                        // physics[0xE0]
J_drive   = driveline_inertia                     // physics[0xE4]
inv_d     = 1 / (total_ratio² / J_drive)           // = J_drive / total_ratio²
k         = inv_d / (K·J_engine + inv_d)           // K = DAT_0060E028 = 4.0

// 2. две инерции сводятся к одной скорости
rpm_free = rpm_engine + M_engine / engine_inertia   // как если бы сцепление было выжато
shaft    = wheel_shaft · total_ratio                 // скорость со стороны колёс
delta    = (shaft − rpm_free) · k
engage   = 1 − clutch                                // ← вот оно, сцепление

shaft' = (rpm_free + delta − shaft) · engage · 0.999 + shaft
rpm'   = rpm_free + delta · engage · 0.999

car.engine_rpm    = rpm'
car.wheel_shaft   = shaft' / total_ratio
clutch_torque     = (engage · delta / k²) · 10        // → car+0x1E24
```

Это **классическая двухинерционная связь**: за шаг каждая сторона сдвигается к
общей скорости в пропорции своих инерций, а `engage = 1 − clutch` масштабирует,
насколько сильно связь вообще включается. Момент сцепления (`car+0x1E24`) затем
раздаётся по колёсам:

```
для каждого колеса:
    force = (Δshaft / Σ|drive|) · wheel.drive / wheel.radius
    wheel.ang_vel += force ;  wheel.force += force · wheel.radius
```

Связь колёс одной оси (дифференциал) решается отдельным проходом: для пар колёс
считается расхождение угловых скоростей и подтягивается с силой
`dt·50·|Δω|·0.1·diff_lock` (не более 1.0) — то есть `diff_lock` работает как
коэффициент сцепления полуосей, 0…1.

Нейтраль: `gear = 0` → `ratio[0] = 0` → привод не связывается с двигателем,
двигатель крутится свободно (ветка `uVar9 & 0x4000` в шаге).
Задний ход — отрицательное число в `ratio[7]`.

### 4.1 Переключение передач — **это native**, не скрипт **[КОД]**

Исправление предыдущей версии этого документа. Автомат КПП живёт в exe и
состоит из трёх функций; `car.gear` (`0x1DF8`) пишут **только** они:

| Функция | Роль |
|---|---|
| `0x0044D720(physics, car)` | главный контроллер: нейтраль/первая/задняя, вызов расписания |
| `0x0044D4F0(physics, car, rpm_rad, M_now, shaft_rpm)` | **апшифт** |
| `0x0044D620(physics, car, rpm_rad, M_now)` | **дауншифт** |
| `0x0044D410` | средний `wheel+0x11C` по ведущим колёсам; `|v| ≥ 0.2` блокирует переключение |

Вход контроллера — **разница педалей**: `fVar4 = throttle(0x1DB4) − brake(0x1DB8)`.

```
Апшифт (0x44D4F0):
  условия: car[0x1E0C] ≤ 0                      // нет незавершённого переключения
           и (|ratio| ≤ 0.01 или |rpm_двиг − rpm_вал| ≤ 0.1·rpm_двиг)  // сцепление сомкнуто
           и gear < gears
  next_ratio = physics[0x24 + gear*4]            // ratio[gear+1]
  rpm_next   = (rpm / ratio_now) * next_ratio
  M_next     = (rpm_next < RPM_limit) ? table1(rpm_next) : 0
  порог      = 0.95 · min(RPM_limit, maxRPM)
  переключить если:  rpm > порог
                ИЛИ  M_now·ratio_now < M_next·next_ratio     // момент на колесе больше
  → gear += 1;  car[0x1E04] = now + 0.3 c;  событие/звук (0x44D040)

Дауншифт (0x44D620):
  условия: car[0x1E10] ≤ 0  и  gear > 1
  prev_ratio = physics[0x1C + gear*4]            // ratio[gear-1]
  rpm_prev   = (rpm / ratio_now) * prev_ratio
  переключить если:  rpm_prev < порог
                И  M_now·ratio_now·1.15 < M_prev·prev_ratio   // гистерезис 15%
  → gear -= 1;  car[0x1E04] = now + 0.2 c
```

Главный контроллер (`0x44D720`) дополнительно:

- обороты холостого хода `idle` — из `physics+0xEC` (рад/с);
- **первая передача** включается при `throttle − brake > 0.1` и `rpm > 3·idle`;
- **нейтраль** — когда `|wheel_shaft| ≤ 1` и `rpm < 1.2·idle`, и когда газ/тормоз отпущены;
- **задний ход** — при `throttle − brake < −0.1` (то есть по **тормозу**), затем
  `0x1DB4` и `0x1DB8` меняются местами, чтобы тормоз стал «газом» —
  это и есть аркадный реверс SLRR;
- `car[0x1E00]`, `[0x1E04]`, `[0x1E0C]`, `[0x1E10]` — таймеры/флаги блокировки.

### 4.2 Сцепление: **автоматическое**, педали нет **[КОД]**

`car+0x1DBC` пишут только native-ассистенты; в скриптах записи нет:

| Функция | Что делает |
|---|---|
| `0x0044DD70(physics, car, dt)` | старт/защита от заглохания: задаёт целевую точку проскальзывания |
| `0x0044E120(physics, car)` | антипробуксовка: приподнимает сцепление и режет газ |
| `0x0044D330`, `0x00447830` | аварийно ставят `clutch = 1.0` (выжато) |

Алгоритм `0x0044DD70` (выходы: нет газа, нет передачи, `|ratio| < 0.01`):

```
idle = physics[0xEC]                                        // рад/с
цель = (physics[0x10]·0.10471976 − idle)
       · (|ratio/ratio[1]| · throttle · 0.7 + 0.3) · 0.8 + idle
                                                     // физика[0x24] = ratio[1]
```
То есть целевые обороты — от `0.8·(idle + 0.3·(limit−idle))` без газа до
`0.8·(idle + (limit−idle))` при полном газе, масштабированные отношением
текущей передачи к первой.

Скорость изменения — с ограничением (константы из бинарника):
`rate = dt · 33.333336` (τ ≈ 30 мс) при движении к меньшему значению и
`rate = dt · 200` (τ ≈ 5 мс) при движении к большему; затем `rate ≤ 1`.
Порог низкой скорости: `|ω_вал · ratio · rearend| ≤ 0.02·2π · min(RPM_limit, maxRPM)`
(`0.12566371`).

### 4.3 Интегрирование — на шаг, а не на секунду **[КОД]**

В блоке двигателя и связи с приводом **`dt` не участвует**:
`rpm += M / engine_inertia` и `shaft' = …·engage·0.999 + shaft` выполняются
один раз за вызов `0x00454500`. `dt` явно входит только в:
релаксацию/трение шины, диффенциал (`dt·50`), тормоза (`dt·50`), износ,
расход закиси и опоры двигателя. То есть «инерции» в этих местах фактически
уже умножены на шаг интегрирования.

Износ в этой же ветке **[КОД]**:

```
car[0x1E24] = ((engage · delta) / k²) · 10          // мера проскальзывания, НЕ момент
износ сцепления (0x1E40) += |delta · engage · 0.1| · mul
износ КПП      (0x1E50) += (|car[0x1E24]| · 0.01)⁴ · dt · 1e-4 · mul
```

`car+0x1E24` читается **только** в формуле износа КПП (`0x454500`, строка 711)
и нигде не используется как момент. `Transmission.capacity` в native-коде не
участвует.

## 5. Шины

### 5.1 Как из компаунда получаются физические параметры — `Tyre.java` **[СКРИПТ]**

```
// SetInflation(P):
k_infl     = (P < P_opt) ? P/P_opt : P_opt/P        // 0…1
k_shape    = k_infl³·0.6 + 0.4
k_sidewall = (profile_ratio · P_opt) / P

insider_friction = friction · (0.5 + 0.5·(tyre_width/275)) · fric_mul   // fric_mul = 1.3
loadcap = 4000
        + ((((0.75 + (profile_ratio/0.4)·0.25) · (0.9 + 0.1·k_sidewall)
             · (tyre_width − 165) · 9.81 · load_mul · 1.35) / friction) / fric_mul)
loadcap /= rubber_rigidity
CPatchAngle = (π/180) · (CPatchMinA + ((0.6 + ((405 − width)/405)·0.4)
                                         · profile_ratio) · (CPatchMaxA − CPatchMinA))
            // CPatchMinA = 4°, CPatchMaxA = 16°
stiffness = clamp(−18 + ((1 − slide_interval)·(1 − profile_ratio))
                        · (0.5 + 0.5·k_shape) · 80, 8, 40)
radius    = (wheel_radius + tyre_width·profile_ratio) / 1000
rollres   = k_shape · min_rollres
par_8     = 1.055 + (insider_friction − 1.0)·0.045
```

Компаунды (`SetupRubber`) — единственное место, где задаётся «держак»:

| Компаунд | `rubber_rigidity` | `load_mul` | `min_rollres` | `sliction` | `loadsmooth` |
|---|---|---|---|---|---|
| street (hard) | 1.00 | 0.75·10.5 | 0.0055·0.725 | 0.695·1.1 | 0.5 |
| sport | 0.90 | 0.8·10.5 | 0.005·0.725 | 0.74·1.1 | 0.3 |
| supersport | 0.75 | 0.8·10.5 | 0.004·0.725 | 0.76·1.1 | 0.25 |
| drag radial | 0.55 | 1.8·10.5 | 0.002·0.725 | 0.72·1.1 | 0.75 |

после чего `friction = ((1.3 + ((friction−1)/0.8)·0.4)) · 1.15`, то есть
«мягкая» резина даёт больший коэффициент.

### 5.2 Что получает native — `WheelRef` **[КОД]**

`setFriction`, `setStiffness`, `setMaxLoad`, `setLoadSmooth`, `setRadius`,
`setWidth`, `setRollRes`, `setBearing`, `setSliction`, `setFrictn_x`,
`setCPatch`, `setPacejka(i, v)` — 17 коэффициентов магической формулы (Pacejka)
в массиве `wheel[0x1E8 + i·4]`, `i = 0…16`.

`Tyre.java` заполняет их так: `[1]=0, [3]=0, [5]=0, [6]=0, [7]=0, [8]=−1,
[9]=0, [10]=0, [12]=1`; `[2]` = `insider_friction` (через `setFriction`).

Износ шины — `wheel[0x15C]`, 0…1. Он напрямую уменьшает оба продольных/поперечных
коэффициента и скорость реакции:
```
f = 1 − wear²·0.4   (при wear ≥ 1 → 0.5)
wheel[0x70] = f · wheel[0x68];  wheel[0x6C] = f · wheel[0x64]
```
При `wear = 1` — **разрыв шины**: радиус `×0.8`, частицы, звук
(`FUN_00491F80`, `FUN_0048CFB0`), повреждение диска (`wheel[0x16C]`).

Отдельно `car+0x1E38` (износ двигателя) и `car+0x1E48` дают тот же множитель
`1 − w²·0.6` — то есть один и тот же закон деградации применён к двигателю и
опорам.

### 5.3 Модель силы в пятне контакта — `0x0043BA80`, `0x0043BB30`, `0x0043BBD0` **[КОД]**

Сила шины — не таблица и не чистый Pacejka, а **двойной atan-вариант Magic
Formula** с экспоненциальным спадом по нагрузке. Для колеса с коэффициентами
`C0…C10` и скольжением `s`:

```
m      = s·C1 + C2                       // база коэффициента трения
C0m    = m · C0                         // C0 — форма кривой
_e      = exp(−s·C5)
num    = (s·C3 + C4) · _e
arg    = (s·C9 + C10 + slip_angle) · (num / C0m)
t1     = atan(arg)
t2     = atan((s·C7 + s²·C6 + C8) · (t1 − arg) + t1)
F      = m · s · sin(C0 · t2)
F      = max(F, 0)
```

`C0…C10` — первые 11 слотов из 17 (`setPacejka`), массив — `wheel+0x1E8`.
Скрипт `Tyre.java` заполняет только часть (`[1]=0,[3]=0,[5]=0,[6]=0,[7]=0,
[8]=−1,[9]=0,[10]=0,[12]=1`), а `[2]` — через `setFriction`, то есть **основной
коэффициент трения приходит из компаунда** (§5.1), а не из таблицы.

Сглаживание скольжения — `0x0043BBD0`: ниже порога `DAT_0060E040` берётся
«статическое» решение напрямую, выше — смешивается с решением, ограниченным по
скорости сходимости (клампы `DAT_0060E02C`/`DAT_0060E030`), что убирает
выбросы силы на малой скорости.

Продольное/поперечное складываются в «круг трения» через угол контакта
(`wheel+0x214` — предельный угол пятна, `0x220` — вес между моделями,
`0x224/0x228` — параметры сглаживания нагрузки, фильтр в `wheel+0x1F8`).

## 6. Подвеска и рулевое

`Spring` **[СКРИПТ]**: `force` (жёсткость, Н/м, по умолчанию 20000), `damping`
(2000), `restlength` (0.39), `minlength` (0.1), `maxlength` (0.3),
`designedMassOnWheel` (300).

`ShockAbsorber`: `damping` (500), `max_damping`, `min_damping`, `min_length`
(0.15), `max_length` (0.45), `rebound_factor` (1.0) — регулируемый отбой;
`whats_inside` = газ / масло / газ+масло.
`Pneumatic_ShockAbsorber` — пневмо: `damping` 5000, `Up_length`, `Down_length`,
`Cur_length`, режимы.

`Swaybar`: `force`, `damping`. `Suspension` (кинематика): `camber`, `toe`, `side`,
`VICx/VICy` (виртуальный центр качения), `LICy/LICz` (мгновенный центр);
`DoubleWishbone`/`McPhersonStrut` передают геометрию через `WheelRef.setArm`,
`setHub`, `setInstantCenter`.

Native (`0x00454500`) по колесу (страйд 0x2B4) держит:
`0xEC` — шаг релаксации, `0x140/0x144/0x148` — сила/импульс контакта,
`0x15C` — износ шины, `0x16C` — повреждение диска, `0x174` — жёсткость,
`0x178/0x17C/0x180` — ход/покой/демпфирование подвески, `0x1E0` — привод.

Ограничители хода отрабатываются явно: при выходе за `max_length` усилие
обрезается, а повреждение растёт (`0x00491F80` создаёт эффект «пробоя»).

Рулевое: `Chassis.max_steer = 0.7`, `setAckermann`, `setSteerWheelRadius`,
`setSteerWheel`; в шаге угол доворачивается по скорости (в коде — `wheel+0x21C`,
там же фиксируется «полный выворот»).

## 7. Тормоза

`Brake` **[СКРИПТ]**: `friction`, `radius`, `force`, `torque = force·friction·radius`;
у деталей также `friction_pad`, `friction_disc`, `number_of_calipers`, `diam_mm`.
`Chassis.brake_balance` (0.5) — распределение осей, `brake_balance_can_be_set`.

Native **[КОД]**: `setBrake`/`setHBrake` пишут номинальные значения в `wheel+0xD0`
и `+0xD4`, а действующие (`+0xD8`, `+0xDC`) пересчитываются с учётом износа диска
(`wheel+0x164`) по тому же закону `1 − w²·0.6`. Тормозной момент в шаге:

```
M_brake = physics[0x37] · handbrake · wheel[0xDC]        // ручник, ось 2
        + (wheel[0xFC] + brake) · physics[0x36] · wheel[0xD8]  // рабочий тормоз
        + wheel[0xF0]                                     // добавка от износа
если M_brake > 0:
    Δω = dt · 50 · wheel.relax · M_brake · const
    колесо подтягивается к нулю не более чем на Δω (без перелёта через 0)
```

то есть `physics[0x36]`/`[0x37]` — баланс тормозов по осям (`brake_balance`),
а `wheel+0xFC` — вклад конкретной детали `Brake`.
Износ тормозов: `wheel[0x188] += (M_brake − wheel[0xF0]) · 10 · |ω| · dt · 50 · 0.001`,
и при `wheel[0x164] ≥ 1` тормоз отключается: `wheel[0xF0] += 100`,
эффективность `×0.2`, искры.

## 8. Аэродинамика

`Chassis.fully_stripped_drag = 0.333`, у моделей — 0.53…0.61;
`C_drag` считает скрипт: `C_drag = max(0, fully_stripped_drag − Σ drag_reduction)`
(`Chassis.updatevariables`). Native читает `drag_center` (Vector3) и `C_drag`
в `0x00448430` и кладёт в `physics+0x23F…0x242`. Крылья (`Wing`) задают
`wing_F` (прижимная сила) и `wing_dir` — они попадают в `physics+0x908` (сила)
и `physics+0x8FC` (точка приложения).

Прижимная сила считается в шаге **[КОД]** как квадратичная по скорости и
прикладывается в точке крыла:

```
v_acr = скорость тела в точке крыла
F     = −|v|² · wing_F
импульс = F · dt, приложенный в physics+0x8FC
```

Там же гасится энергия превышения (ограничение импульса по `max`), то есть
крыло не может «выстрелить» машину при большом dt.

| Объект | Поле | Как растёт | Множитель |

| Шина | `wheel+0x15C` | пропорционально силе×скорости | `1 − w²·0.4`, при `w≥1` разрыв |
| Тормозной диск | `wheel+0x164` | по работе торможения | `1 − w²·0.6`, при `w≥1` отказ |

Износ сцепления и КПП считается **от проскальзывания и переданного момента**, а
не от `Transmission.capacity` — этот параметр в native не участвует.

### 9.1 Порядок шага `0x00454500` (восстановлен полностью)

1. ранний выход: `car+0x1FC0 != 0` или `dt < 1e-4`;
2. двигатель: обороты, трение, момент по таблице, стартер, закись, отсечка (§3.5);
3. износ двигателя и опор (§3.5, §3.6);
4. трансмиссия: двухинерционная связь, момент сцепления, износ (§4);
5. раздача момента по колёсам через `drive`/радиус;
6. дифференциал: выравнивание угловых скоростей пар колёс (§4);
7. шины: скольжение → сила → импульс в пятне контакта (§5.3);
8. подвеска: пружина/демпфер, ограничители хода, стабилизатор → импульс;
9. тормоза и ручник (§7), износ тормозов;
10. поворот колеса (`wheel+0xE8` — угол, накапливается по угловой скорости);
11. крыло и аэродинамика (§8);
12. внешние силы (`0x1F00`, `0x1F04`, `0x1F08`) и телеметрия подвески;
13. износ кузова и деталей (`0x0043C260`).

## 11. Что ещё не восстановлено

Шаг `0x00454500` прочитан **полностью** (1497 строк). Остались точечные вопросы,
а не целые блоки:

1. **Точный смысл `0x1F00`** — сила с направлением от угла руля `0x1DAC`,
   приложенная в точке `(0, −0.2, 2)`, масштаб 20. Похоже на «усилие на рулевое»
   или внешний импульс; нужно проверить, кто пишет это поле.
2. **`0x1F04`/`0x1F08`** — внешние силы (толчок/удар): пишутся извне,
   точка записи в скриптах не найдена.
3. **`physics[0x36]/[0x37]`** (баланс тормозов): значения берутся из прототипа
   объекта физики; точку их установки из `brake_balance` надо добить.
4. **Турбояма**: подтвердить, что в рантайме нет отдельной динамики наддува
   (сейчас все признаки за это: таблица №2 включается только через закись).
5. **`0x00447830`** — альтернативная ветка шага (при `flags & 4`), не разобрана;
   она же вызывается для «замороженного» автомобиля.
6. **Таблицы момента по каждому двигателю** — их проще снять со стенда (§13),
   чем пересчитывать термодинамику.

## 13. Предлагаемые следующие шаги

1. **Стенд на живой игре.** Внедриться в процесс (32-бит) и снять по каждому
   двигателю: таблицы `torque`/`torque2`, `ClutchF`, отсечку, поведение наддува.
   Это закрывает §11.6 и §11.4 фактами, а не чтением кода. Точки входа известны
   (`physics` = `[car+0x1FBC]`, таблицы — `physics+0x04`, `physics+0x0C`).
2. **Проход по структурам в Ghidra.** Объявить типы `CarPhysics` (0xC1C),
   `Wheel` (0x2B4) и переименовать поля — после этого декомпиляция
   `0x00454500` читается напрямую, и оставшиеся 60 % разбираются за один проход.
3. **Перенос по частям, с тестами:** (a) таблицы момента + отсечка, (b) сцепление
   `1−clutch` без `ClutchF`, (c) дифференциал, (d) шина по параметрам §5,
   (e) подвеска, (f) износ.
4. **Сверить с `PHYSICS_MODEL_PROVENANCE.md`**: пункт про `ClutchF` как «главное
   расхождение» теперь уточнён — параметр не используется оригиналом (§3.8).
