# Как добавить переводы в мод для SLRR Light Edition

Это руководство для авторов модов. Не нужно изучать Java или Tufa: мы будем копировать готовые фрагменты, менять названия и тексты, а затем сохранять файлы.

Инструкция предназначена для **SLRR Light Edition с установленным Localization Manager**. На обычной версии SLRR и на сборках Light Edition без Localization Manager этот способ не работает.

---

## Самое важное перед началом

- Переводы хранятся **в самом моде**, а не в общих файлах игры.
- Для всех языков мода нужен **один файл локализации**.
- В текущей версии игры доступны английский (EN), русский (RU) и польский (PL).
- Русский и польский текст можно писать **обычными буквами прямо в кавычках**. Никаких конвертеров, HEX-кодов или `\\xNN` не требуется.
- Моды без локализации продолжат работать как раньше. Добавлять им файлы или менять их исходники не нужно.

Если для выбранного языка не найден перевод, игра использует английский перевод из словаря. Если и его нет, будет показан исходный текст, который уже был указан в моде.

## Что можно перевести

С помощью готовых методов Light Edition можно задать:

| Что переводим | Для чего используется |
|---|---|
| Название автомобиля | Имя автомобиля в интерфейсе |
| Название шасси | Название базового объекта автомобиля |
| Описание шасси | Описание автомобиля |
| Название детали | Имя детали в инвентаре и окнах информации |
| Описание детали | Описание детали |
| Собственные надписи мода | Например, текст кнопки или сообщения в собственном окне |

Для названий и описаний автомобиля и деталей предусмотрены готовые методы. Для собственных окон есть отдельный короткий пример ниже.

# Часть 1. Подготовка

## Что понадобится

- SLRR Light Edition с работающим Localization Manager.
- Папка исходников вашего мода.
- Редактор обычного текста: например, Notepad++, VS Code или другой редактор, которым вы уже пользуетесь.
- Резервная копия папки мода.

**Важно:** нужны исходные файлы `.java`. Не редактируйте `.class` — это уже собранные файлы игры. Переименование `.class` в `.java` не восстановит исходный код. Если у вас есть только `.class`, попросите исходники у автора мода.

## Как обычно устроена папка автомобиля

Например:

```text
cars/
└── racers/
    └── My_Car_data/
        └── scripts/
            └── src/
                ├── My_Car.java
                └── ... другие исходники автомобиля
```

`My_Car.java` здесь — главный исходник автомобиля. У вашего мода имя файла и папки будут другими.

Сначала сделайте копию папки мода. Если что-то пойдёт не так, вы сможете вернуть исходные файлы.

# Часть 2. Создаём один файл переводов

В этой части мы добавим переводы условного автомобиля `My Car`.

## Шаг 1. Создайте файл

В папке `src`, рядом с главным исходником автомобиля, создайте новый файл:

```text
Localization_My_Car.java
```

Название после `Localization_` можете выбрать сами. Важно, чтобы имя файла и имя класса внутри него совпадали. В примере ниже они уже совпадают. Например, если вы назвали файл `Localization_Opel.java`, строка класса внутри должна быть `public class Localization_Opel`, а в строке подключения нужно будет написать `Localization_Opel.getDictionaries()` .

## Шаг 2. Проверьте строку package

Откройте главный файл автомобиля `My_Car.java`. В самом начале найдите строку, начинающуюся со слова `package`. Например:

```java
package java.game.cars;
```

В новом `Localization_My_Car.java` первая строка должна быть **точно такой же**. Если в исходнике вашего автомобиля указано другое значение, скопируйте именно его.

## Шаг 3. Вставьте готовый код

Скопируйте в `Localization_My_Car.java` весь пример ниже. Потом замените примеры названий и описания на тексты своего мода.

```java
package java.game.cars;

import java.game.*;

public class Localization_My_Car
{
    static LocalizationMap cachedDictionaries;

    public static LocalizationMap getDictionaries()
    {
        if( cachedDictionaries != null )
            return cachedDictionaries;

        LocalizationMap all = new LocalizationMap();

        // ENGLISH
        LocalizationMap en = new LocalizationMap();
        en.put( "vehicle.name", "My Car" );
        en.put( "chassis.name", "My Car chassis" );
        en.put( "chassis.description", "English description of the car." );
        all.put( "en", en );

        // РУССКИЙ
        LocalizationMap ru = new LocalizationMap();
        ru.put( "vehicle.name", "Моя машина" );
        ru.put( "chassis.name", "Шасси моей машины" );
        ru.put( "chassis.description", "Описание моей машины на русском языке." );
        all.put( "ru", ru );

        // POLSKI
        LocalizationMap pl = new LocalizationMap();
        pl.put( "vehicle.name", "Mój samochód" );
        pl.put( "chassis.name", "Podwozie mojego samochodu" );
        pl.put( "chassis.description", "Opis mojego samochodu w języku polskim." );
        all.put( "pl", pl );

        cachedDictionaries = all;
        return cachedDictionaries;
    }
}
```

**Русские и польские слова здесь написаны обычными буквами.** Пишите свои переводы так же — прямо между кавычками. Не нужно преобразовывать текст в специальные последовательности.

### Что здесь менять, а что оставлять

В строке:

```java
en.put( "vehicle.name", "My Car" );
```

- `vehicle.name` — ключ. Это короткое имя конкретной строки. **Не меняйте его**, если не собираетесь менять тот же ключ в местах подключения перевода.
- `My Car` — сам текст, который увидит игрок. Его нужно заменить на название вашего автомобиля.

В каждом языке ключи слева должны совпадать. Текст справа будет разным:

```java
en.put( "vehicle.name", "My Car" );
ru.put( "vehicle.name", "Моя машина" );
pl.put( "vehicle.name", "Mój samochód" );
```

Если пока нет перевода на какой-то язык, можно не добавлять запись для этого языка. Например, если нет польского перевода, удалите или не добавляйте польскую строку. При выборе PL игра попробует английский перевод, а если его нет — исходный текст мода.

Не удаляйте технические строки и не переименовывайте `Localization_My_Car`, `getDictionaries`, `LocalizationMap`, `en`, `ru` и `pl`.

# Часть 3. Добавляем файл локализации в RPK мода

Это обязательный шаг. Одного файла `Localization_My_Car.java` недостаточно: игра должна знать, что скомпилированный файл `Localization_My_Car.class` является ресурсом вашего мода. Для этого добавляется запись в RPK автомобиля.

**Не пугайтесь названий `.res` и `.rsd`.** Это не два отдельных файла, которые нужно создавать в Windows. Это две части одной записи внутри текстового представления RPK.

## Шаг 1. Найдите RPK своего мода

Обычно у автомобиля есть RPK рядом с папкой данных. Например:

```text
cars/
└── racers/
    ├── My_Car.rpk
    └── My_Car_data/
        └── scripts/
            └── src/
                ├── My_Car.java
                └── Localization_My_Car.java
```

Перед изменениями сделайте копию `My_Car.rpk`.

## Шаг 2. Откройте RPK как текстовую базу ресурсов

RPK нельзя просто открыть и отредактировать в обычном текстовом редакторе. Сначала преобразуйте его в текстовый RDB с помощью `resdecode` или совместимого Resource Tools GUI. Откройте получившийся `.rdb` в Notepad++, VS Code или другом текстовом редакторе.

После изменений RDB нужно будет собрать обратно в RPK с помощью `resconvert` или соответствующей команды в Resource Tools GUI.

## Шаг 3. Добавьте запись локализации

В конец RDB добавьте следующий блок. Это пример для `My_Car`; путь и идентификаторы нужно подстроить под свой мод.

```text
<FILE 00000347.res >
typeof 8
superid 0x00000104
typeid 0x0000A390
alias localization
isparentcompatible 1.00
</FILE>
<FILE 00000347.rsd >
script cars\racers\My_Car_data\scripts\Localization_My_Car.class
lod_amp 3.000
</FILE>
```

Важные правила:

- Число `00000347` — номер этой записи в RPK. Он должен быть свободным в RDB. Если такой номер уже есть, выберите другой. Число в `.res` и `.rsd` **обязательно должно совпадать**.
- `typeid 0x0000A390` — ещё один идентификатор ресурса. Он должен быть уникальным среди `typeid` в этом RPK. Если значение уже используется, выберите другое свободное значение.
- `superid 0x00000104` оставьте именно таким, как в примере. Это часть типа/категории ресурса, а не ID, который нужно придумывать для каждого мода.
- `alias localization` можно оставить без изменений.
- Путь после `script` должен указывать на **скомпилированный `.class`**, а не на `.java`. В нашем примере исходник находится в `scripts/src`, но путь в RPK ведёт в `scripts` — без папки `src`.
- Путь должен соответствовать реальному расположению файла внутри папки игры. Замените `My_Car` и имя файла на названия из своего мода.

`typeof 8` — тип записи для скриптовых ресурсов. В RPK такие записи используются для `.class` и связанных с ними игровых скриптов.

## Что делать с `isparentcompatible` и `lod_amp`?

Для этого шага ничего придумывать не нужно — оставьте обе строки такими, как в проверенном примере:

```text
isparentcompatible 1.00
lod_amp 3.000
```

`isparentcompatible` по названию относится к совместимости ресурса с родительским типом. Точная внутренняя логика этого флага в доступной документации подробно не описана; руководства по RPK советуют его не трогать. Для нашего файла оставьте `1.00`.

`lod_amp` встречается в RPK-записях, связанных с LOD (Level of Detail — уровни детализации), в том числе в некоторых записях скриптов и объектов с моделями. Точное влияние этого параметра именно на запись, которая ссылается только на класс локализации, достоверно не описано. Поэтому используйте проверенное значение `3.000` и не пытайтесь его настраивать. Мы также не проверяли, можно ли безопасно удалить эту строку.

## Шаг 4. Соберите RPK обратно

Сохраните RDB и преобразуйте его обратно в `My_Car.rpk` через `resconvert` или Resource Tools GUI. Убедитесь, что итоговый RPK заменил старую копию в папке мода.

После компиляции исходника должен существовать файл:

```text
cars/racers/My_Car_data/scripts/Localization_My_Car.class
```

Именно на него указывает запись `script` в RPK. Не указывайте путь к `src/Localization_My_Car.java`.

**Важно:** если в моде нет локализации, добавлять такую запись в RPK не нужно. Старые моды без локализации продолжат работать как раньше.

# Часть 4. Подключаем переводы к автомобилю

Файл со словарём уже создан. Теперь нужно один раз указать автомобилю, какие именно строки из него использовать.

## Шаг 1. Откройте исходник автомобиля

Откройте `My_Car.java` и найдите конструктор. Это участок, который начинается примерно так:

```java
public My_Car( int id )
{
    super( id );
```

Внутри конструктора найдите исходные английские значения `vehicleName`, `name` и `description`. Пример:

```java
vehicleName = "My Car";
name = "My Car chassis";
description = "English description of the car.";
```

У вашего автомобиля текст будет другим. Не удаляйте существующие настройки и характеристики машины.

## Шаг 2. Добавьте строки подключения

Сразу **после исходных присваиваний** `vehicleName`, `name` и `description` вставьте:

```java
localization.registerMod( "my_car_mod", Localization_My_Car.getDictionaries() );
setLocalizedTexts(
    "my_car_mod", "chassis.name", "My Car chassis",
    "chassis.description", "English description of the car."
);
setLocalizedVehicleName( "my_car_mod", "vehicle.name", "My Car" );
```

Замените в примере:

- `my_car_mod` — на короткий уникальный ID вашего мода. Например, `opel_manta_400`. Используйте его одинаково во всех строках подключения.
- `Localization_My_Car` — на имя вашего класса словаря, если вы назвали его по-другому.
- `My Car chassis` — на исходное английское название шасси из вашего файла.
- `English description of the car.` — на исходное английское описание из вашего файла.
- `My Car` в последней строке — на исходное английское название автомобиля.

Ключи `chassis.name`, `chassis.description` и `vehicle.name` должны совпадать с ключами в файле переводов. Можно придумать другие ключи, но тогда они должны быть одинаковыми в словаре и в строках подключения.

### Нужно ли добавлять import?

В начале главного файла автомобиля обычно уже есть:

```java
import java.game.*;
```

Он нужен для обращения к менеджеру локализации. Если такой строки нет, добавьте её под строкой `package ...;`.

Если файл словаря находится в том же пакете (то есть у него такая же строка `package`), отдельный `import` для него не нужен.

## Почему подключение ставится после исходных названий?

Сначала мод записывает оригинальные английские значения. Затем методы локализации заменяют их переводами. Если поставить строки подключения раньше, последующие присваивания могут снова записать английский текст поверх перевода.

# Часть 5. Перевод деталей

Для деталей используется тот же файл словаря. Не создавайте отдельный файл на каждый язык и не создавайте отдельный словарь на каждую деталь.

## Шаг 1. Найдите исходник детали

Откройте `.java`-файл нужной детали и найдите её конструктор и исходные присваивания `name` и `description`.

Например:

```java
name = "My Turbo Kit";
description = "A bolt-on turbocharger kit.";
```

## Шаг 2. Добавьте переводы в общий словарь

В `Localization_My_Car.java` добавьте новые ключи в соответствующие языковые разделы:

```java
en.put( "turbo.name", "My Turbo Kit" );
en.put( "turbo.description", "A bolt-on turbocharger kit." );

ru.put( "turbo.name", "Турбокомплект" );
ru.put( "turbo.description", "Комплект турбонаддува для двигателя." );

pl.put( "turbo.name", "Zestaw turbo" );
pl.put( "turbo.description", "Zestaw turbosprężarki do silnika." );
```

Ключи `turbo.name` и `turbo.description` — примеры. Для других деталей придумайте свои понятные ключи. В пределах одного мода не используйте один и тот же ключ для разных текстов.

## Шаг 3. Подключите перевод к детали

После исходных присваиваний `name` и `description` добавьте:

```java
localization.registerMod( "my_car_mod", Localization_My_Car.getDictionaries() );
setLocalizedTexts(
    "my_car_mod", "turbo.name", "My Turbo Kit",
    "turbo.description", "A bolt-on turbocharger kit."
);
```

Используйте тот же `my_car_mod` и тот же класс `Localization_My_Car`, что и для автомобиля.

**Важно:** если у автомобиля и деталей один общий мод, используйте один общий словарь и один `modId`. В этом словаре должны лежать переводы автомобиля и всех деталей. Не создавайте отдельные словари с тем же `modId`: менеджер регистрирует один набор переводов для каждого ID.

Если деталь находится в другом пакете, чем файл словаря, добавьте в её исходник `import` с полным именем класса словаря. Например, если в словаре указано `package java.game.cars;`, импорт будет таким:

```java
import java.game.cars.Localization_My_Car;
```

Если непонятно, какой пакет указан в исходнике детали, не угадывайте — попросите помочь определить его.

Повторный вызов `registerMod()` с уже зарегистрированным ID безопасен: менеджер не загружает один и тот же набор повторно. Поэтому его можно добавить в конструктор автомобиля и в конструкторы отдельных деталей, если они могут открываться в игре независимо.

# Часть 6. Собственные надписи и окна мода

Если в моде есть собственное окно, кнопка или сообщение, перевод можно получить напрямую.

Например, добавьте в языковые словари ключ `dialog.install`:

```java
en.put( "dialog.install", "Install turbo kit" );
ru.put( "dialog.install", "Установить турбокомплект" );
pl.put( "dialog.install", "Zainstaluj zestaw turbo" );
```

Перед первым использованием `localization.getMod()` словарь должен быть зарегистрирован через `localization.registerMod()`. В простом случае это уже происходит в конструкторе автомобиля или детали. Если собственное окно может открыться раньше, зарегистрируйте словарь в коде запуска этого окна.

А в исходнике окна используйте:

```java
String buttonText = localization.getMod(
    "my_car_mod",
    "dialog.install",
    "Install turbo kit"
);
```

Последний параметр — исходный английский текст на случай, если перевод не найден.

Этот пример нужен только для собственных элементов интерфейса мода. Для обычных названий автомобиля, шасси и деталей используйте готовые методы из предыдущих частей.

# Часть 7. Проверяем результат

1. Сохраните изменённые `.java`-файлы.
2. Запустите игру обычным способом, которым вы проверяете изменения своих скриптов.
3. Выберите RU в настройках игры.
4. Откройте автомобиль или деталь и проверьте название и описание.
5. Повторите проверку для EN и PL.
6. Проверьте хотя бы одну запись, для которой вы намеренно не добавили перевод. Игра должна показать английский вариант или исходный текст.

Не удаляйте оригинальные английские присваивания `vehicleName`, `name` и `description` из исходников. Они нужны как запасной вариант.

# Частые вопросы

### Обязательно ли добавлять локализацию в каждый мод?

Нет. Это необязательно. Мод без файлов локализации и без вызовов Localization Manager продолжает работать по-старому.

### Нужно ли создавать отдельный файл для RU, EN и PL?

Нет. Все языки одного мода хранятся в одном файле `Localization_ИмяМода.java`.

### Можно ли писать кириллицу и польские буквы прямо в файле?

Да. Пишите обычный текст прямо в кавычках, как в примерах. Не используйте конвертеры, HEX-коды или специальные последовательности `\\xNN`.

### Что будет, если перевод не готов?

Игра попробует английскую запись. Если её нет, покажет исходный английский текст из мода. Можно начать с одного языка и добавить остальные позже.

### Можно ли использовать один словарь для нескольких автомобилей и деталей?

Да. Это рекомендуемый вариант для одного мода. Добавляйте в общий словарь отдельные ключи, например `manta.vehicle.name`, `kadett.vehicle.name`, `turbo.name` и `turbo.description`.

### У меня только `.class`, а исходников `.java` нет. Что делать?

По этой инструкции самостоятельно подключить локализацию не получится. Попросите автора мода предоставить исходники или попросите помощи у человека, который сможет внести изменения и пересобрать скрипты.

### Где посмотреть пример работающей локализации?

Посмотрите на файлы `Opel_Manta_400.java` и `Localization_Opel_Manta_400.java` в исходниках SLRR Light Edition. Они показывают, как словарь регистрируется и как к нему подключаются имя автомобиля, название шасси и описание.
