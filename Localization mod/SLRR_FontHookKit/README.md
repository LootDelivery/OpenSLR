# SLRR Native Fonts — Hook Kit (иконки кузова + антикрэш)

Переносимый набор для самостоятельной установки хука «нативных шрифтов» в exe
игры **Street Legal Racing: Redline** (сборки мода *native fonts v4.x gate* и
пересборки того же мода, в том числе с изменениями).

Кит делает то же, что и исправленный exe `..._v42_gate_fixed.exe`, но:
- **не привязан к адресам** — все точки патча ищутся по байтовым сигнатурам;
- **без зависимостей** — скрипт на чистом Python 3 (стандартная библиотека);
- **с откатом** — перед правкой создаётся бэкап, есть `--revert`.

---

## 1. Состав кита

| Файл | Назначение |
|---|---|
| `slrr_font_hook.py` | Универсальный патчер. Анализирует exe, находит все точки по сигнатурам, ставит хук, пересчитывает PE-контрольную сумму, пишет отчёт. |
| `hook_source.asm` | Полный человеко-читаемый исходник машинного кода хука (синтаксис NASM) — для изучения и ручной сборки. |
| `HookReport.example.txt` | Пример отчёта патчера на эталонной сборке v4.1 gate. |
| `README.md` | Этот документ. |

---

## 2. Быстрый старт (патчер)

Нужен Python 3 (на Windows — python.org, при установке отметить *Add to PATH*).

```bat
rem 1. Посмотреть, что хук применим (ничего не пишет):
python slrr_font_hook.py game.exe --check

rem 2. Пропатчить (бэкап создастся автоматически: game.exe.slrr-hook.bak):
python slrr_font_hook.py game.exe

rem 3. Если что-то пошло не так - откат:
python slrr_font_hook.py game.exe --revert
```

Полезные опции:
- `--out FILE` — записать результат в отдельный файл, не трогая исходный exe;
- `--no-backup` — не создавать бэкап (не рекомендуется);
- `--no-report` — не сохранять `game.exe.HookReport.txt`.

После патча отчёт со всеми найденными адресами сохраняется рядом
(`game.exe.HookReport.txt`) — **эти адреса нужны для ручной сборки** `hook_source.asm`.

Патчер сам откажется работать, если:
- exe уже пропатчен этим хуком;
- сигнатуры не совпали (битые/другие сборки) — с точным указанием, что не нашлось;
- SizeOfImage не позволяет расширить секцию под пещеры.

## 3. Что именно чинит хук

### Баг 1 — краш (антикрэш-правка)

В fallback-классификаторе мода был потерян стаб: условный переход
`je` вёл на адрес, где стояли **нули** (не код) — исполнение попадало в
нулевые байты и игра падала. Правка восстанавливает стаб:

```asm
xor eax, eax   ; return 0 -> штатный рендер шрифта игрой
ret
```

### Баг 2 — иконки состояния кузова собираются в одну точку

Иконки схемы кузова (зелёный силуэт машины в гараже/боксе) — это не текст,
а OSDF-шрифт, чьи «глифы» — детали автомобиля, разложенные смещениями из
`.osf`-файла. Экземпляры этого шрифта работают в трёх масштабах (px 15/94/31)
и имеют класс глифов **0** («не текст»).

Классификатор шрифтов мода безусловно отправлял их в TTF-бэкенд:
GDI-метрики для «иконных» символов возвращали ширину в ~10 раз меньше
нужной, игра раскладывала детали схемы по этой сломанной ширине — и все
детали собирались в одну точку (сами формы рисовались штатно, поэтому силуэт
выглядел «правильным», но сжатым в кучу).

Правка: классификатор возвращает «сток» (родной рендер игры) для шрифтов с
классом глифов 0. Вся остальная логика не тронута:
- текстовые шрифты (класс 1 «mono» / 2 «proportional») — через TTF, как и было;
- явные профили (px 7/10/14/20/24/28/40/45) — без изменений;
- fallback для неизвестных размеров текстовых шрифтов — без изменений.

### Как это устроено (двоичное представление)

Классификатор (`0x7E7150` в эталонной сборке) распределяет шрифты:

```
xor eax,eax; add ecx,-7; cmp ecx,0x26
ja  <fallback>          <- SITE-A: известные px идут в jump-таблицу,
push edi; push esi         неизвестные - в fallback
mov esi,1
jmp dword [ecx*4 + <таблица переходов>]
...
<кейс px=15>: mov edi,8; mov esi,3; jmp <эпилог>   <- SITE-B
<эпилог>: mov eax,[esp+0x10]; mov [eax],esi; mov [eax+4],edi;
          mov eax,1; jmp <общий pop/test/ret>
<fallback>: если descriptor+0x20 != 0 -> out={3,8}, return 1 (TTF)
```

Хук добавляет **две пещеры кода** в свободное место секции и перенаправляет
два перехода:

| Правка | Что делает |
|---|---|
| SITE-A (`ja` → cave1) | все «неизвестные» px сначала проходят проверку класса глифов |
| SITE-B (кейс px=15 → cave2) | px=15 тоже проходит проверку класса |
| cave1 / cave2 | ищут descriptor в таблице маршрутизации мода; класс 0 → `return 0` (сток); иначе → оригинальное поведение мода |
| ANTI-CRASH | восстановление стаба `xor eax,eax; ret` на месте je-перехода в fallback |
| VirtualSize | расширяется до SizeOfRawData, если пещеры за пределами (с проверкой SizeOfImage) |
| checksum | пересчёт PE-контрольной суммы |

Отличие cave2 от версии v4.2: TTF-ветка cave2 **детерминированно записывает**
`out={3,8}` тем же способом, что и оригинальный эпилог классификатора
(`mov eax,[esp+0x10]; mov [eax],esi; mov [eax+4],edi`), — не полагаясь на
содержимое стека вызывающего кода. На поведение игры это не влияет, но делает
хук безопасным на пересобранных exe.

## 4. Сигнатуры, по которым патчер ищет точки

Сигнатуры описывают **код**, а не данные, поэтому выживают при пересборке
мода с другими адресами (`??` — любой байт):

| Имя | Сигнатура (hex) | Даёт |
|---|---|---|
| Классификатор | `31 C0 83 C1 F9 83 F9 26 0F 87 ?? ?? ?? ?? 57 56 BE 01 00 00 00 FF 24 8D ?? ?? ?? ??` | SITE-A (`0F 87`), адрес fallback (из rel32) |
| Кейс px=15 | `BF 08 00 00 00 BE 03 00 00 00 EB ??` | SITE-B |
| Таблица маршрутизации | `BA ?? ?? ?? ?? BF ?? ?? ?? ??` (в 0x80 байтах после головы классификатора) | адрес таблицы + число записей (`mov edi,imm/2`) |
| Тело fallback | `8B 4C 24 04 83 79 20 00 74 ?? 8B 44 24 08 C7 00 03 00 00 00 C7 40 04 08 00 00 00 B8 01 00 00 00 C3 31 C0 C3` | crash-сайт (je rel8 → je_addr+2+disp) |
| «Уже пропатчено» | `E9 ?? ?? ?? ?? 90 90 90 90 90 90 90 BF 06 00 00 00` | отказ с внятным сообщением |

Пещеры патчер размещает сам: первый нулевой 16-байт-выровненный блок после
последнего ненулевого байта секции, в который не указывает ни одна
абсолютная ссылка (`imm32` → диапазон пещер ±0x100). Поэтому пещеры никогда
не пересекаются с данными мода (таблица маршрутизации, счётчики и т.п. —
они нулевые в файле, но заполняются в рантайме).

## 5. Ручная правка (без Python, в HxD / xvi32)

Если Python ставить не хочется, можно пропатчить hex-редактором. Адреса —
из `HookReport.txt` (или найдите самостоятельно по сигнатурам из раздела 4;
смещение в файле = `PointerToRawData секции + (VA - ImageBase - RVA секции)`).

1. **SITE-A** — по сигнатуре классификатора найдите `0F 87 xx xx xx xx`
   (после `83 F9 26`). Замените 4 байта rel32 на
   `cave1_va - (addr_of_ja + 6)`, little-endian.
2. **SITE-B** — по сигнатуре `BF 08 ... EB xx` замените все 12 байт на
   `E9` + rel32 + `90 ×7`, где `rel32 = cave2_va - (addr_of_E9 + 5)`.
3. **ANTI-CRASH** — в теле fallback байт после `74` (disp8) указывает на
   crash-сайт: перейдите `je_addr + 2 + disp8` и замените `00 00 00` на
   `31 C0 C3`.
4. **VirtualSize** — в заголовке секции с кодом мода (имя `.ttf`), поле
   VirtualSize (смещение +8 в записи секции) → значение SizeOfRawData.
5. **Checksum** — обнулите поле по смещению OptionalHeader+64, посчитайте
   сумму 16-битных слов с переносом по всему файлу, прибавьте размер файла,
   запишите в поле. (Проще — открыть exe в CFF Explorer и нажать *Update
   checksum*; либо использовать патчер, который делает это сам.)

Готовые байты пещер собираются из `hook_source.asm` (NASM) — см. раздел 7.

## 6. Адаптация под изменённый exe

Хук рассчитан на **тот же мод** (native fonts), возможно с вашими правками.
Патчер автоматически находит:
- классификатор, fallback, таблицу маршрутизации, crash-сайт — по сигнатурам;
- число записей таблицы (`mov edi,imm32` рядом с классификатором, делится на 2);
- свободное место под пещеры;
- необходимость расширения VirtualSize.

Что патчер **не** сможет переварить и честно сообщит об этом:
- изменённая голова классификатора или кейс px=15 (другая логика px-кейсов);
- изменённое тело fallback (anti-crash правка будет пропущена с
  предупреждением, иконный фикс всё равно применится);
- SizeOfImage без запаса под расширение секции.

Если вы изменили **логику** мода (например, другие профили px) — правьте
`hook_source.asm`: константы `CLASS_STOCK`, `OUT_SLOT`, `OUT_PROFILE`,
адреса — и пересобирайте (раздел 7). Структура таблицы (stride 0x38, класс в
`entry+8`) захардкожена в моде и в хуке.

---

## 7. Сборка hook_source.asm вручную

```bat
nasm -f bin hook_source.asm -o hook.bin
```

Перед сборкой впишите в блок КОНФИГ адреса **вашей** сборки из
`HookReport.txt` (`CAVE1_VA`, `FALLBACK_VA`, `TABLE_VA`, `ENTRIES`).
Полученный `hook.bin` записывается в exe по адресу `CAVE1_VA`
(файловое смещение считайте как в разделе 5), затем правятся точки
SITE-A / SITE-B / ANTI-CRASH по инструкциям внизу `.asm` и в разделе 5.

Патчер и `.asm` генерируют идентичный машинный код: байт-в-байтовая сверка
проводилась на эталонной сборке (дизасм обеих пещер совпадает, включая все
относительные переходы).

---

## 8. Проверка после патча

1. Гараж/бокс: схема кузова внизу справа разложена по деталям (капот, двери,
   бампера — каждые на своём месте), как в ванили; во всех трёх масштабах.
2. Шрифты меню/HUD — визуально без изменений (текст по-прежнему TTF).
3. Прежние краши, связанные с классификатором, не воспроизводятся.
4. Если ведёте лог: для иконных стримов (px=15/94/31, class=0) появляются
   строки fallback-рендера вместо аномально коротких TTF-замеров ширины.

## 9. Откат

```bat
python slrr_font_hook.py game.exe --revert
```
восстанавливает exe из `game.exe.slrr-hook.bak`. Бэкап создаётся при каждом
патче поверх исходного файла (при `--out` бэкап не нужен — исходник не трогается).

---

## 10. Известные ограничения

- Хук рассчитан на 32-битный PE (PE32) и сборки мода native fonts; на
  ванильном exe (без этого мода) сигнатуры не найдутся — патчер откажется
  работать с точным указанием, чего не хватает.
- stride записи таблицы (0x38) и смещение класса (entry+8) соответствуют
  моду и не вычисляются автоматически.
- Если мод пересобран так, что свободного места под пещеры нет (нужно ~0xD0
  нулевых байт в секции кода), патчер сообщит об этом — придётся расширять
  секцию вручную.
